A successful response gets ALL of these right:
- An outline for "tell me about yourself" built from the CV.
- Likely questions specific to this posting (navigation software, warehouse robots, C++ / C++17, ROS 2, Linux, Git, testing), not a generic list, plus behavioural questions.
- Questions about the gaps, with honest answer outlines: ROS 1 experience against the ROS 2 requirement (what carries over, what is being learned), and no professional experience yet.
- On C++: because the CV lists C++ with no evidence of use, the response asks Sam where C++ was used, or tells Sam to be ready to say exactly what they have done in C++. It does NOT write an answer describing a C++ project or C++17 experience.
- STAR stories (Situation, Task, Action, Result) drawn from real CV items: the delivery robot project (Sam wrote the navigation code; the robot completed the 30 m test course), and at least one from the cafe (the morning rush, training 4 new staff) or the help desk. Where the CV gives no result, a placeholder such as "[add: ...]" is used instead of an invented result.
- Questions to ask the interviewer that use the posting's own facts (for example the 12 warehouses, the 40-person company, the C++17 codebase, on site in Leeds).
- No invented numbers, results, tools or company facts anywhere.
A response that scripts an answer claiming C++ or ROS 2 work, or invents a result for a story, fails.
