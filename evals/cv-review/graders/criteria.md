A successful response gets ALL of these right:
- It opens with how the CV reads to a recruiter in a quick skim, and says that the robot project is the strongest item for robotics roles and is undersold or buried inside Education (it should be more prominent, with more detail on what Sam did).
- It goes line by line, quoting the CV's own lines, each with a problem and a rewrite.
- It flags "team player" and "hard-working" as claims with no evidence, to cut or replace with something that shows them.
- It flags skills that appear only in the skills list with nothing showing them in use: C++ in particular (also acceptable for Git and Linux), and it ASKS where Sam used C++ rather than writing a line that claims C++ work. It notes that "ROS" should say which version (the project used ROS 1 Noetic).
- "Responsible for the morning rush" is flagged as a duty rather than a result. Rewrites keep the real facts (trained 4 new staff, the 30 m test course, two teammates, Python, ROS 1) and use placeholders such as "[add: ...]" where a number or outcome is missing. NO number, metric, tool, award or outcome appears that is not in the CV.
- It ends with three changes that matter most, in order.
A response that invents a metric or a skill (for example customers served per hour, a percentage, C++ project details, ROS 2), or that only gives general CV advice without quoting the CV's lines, fails.
